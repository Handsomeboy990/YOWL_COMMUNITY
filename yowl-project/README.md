# YOWL Community

Social platform where members publish short reviews about a link or a media,
react to them, comment, and moderate the content together. The interface is in
French; the code and this documentation are in English.

## Stack

| Layer | Technology |
|---|---|
| API | Laravel 12, PHP 8.2 or later |
| Authentication | Laravel Sanctum (bearer tokens), spatie/laravel-permission for roles |
| API documentation | dedoc/scramble (OpenAPI) |
| Web push | minishlink/web-push (VAPID) |
| Frontend | Vue 3, Vite 7, Pinia, Vue Router, Tailwind CSS 4 |
| PWA | vite-plugin-pwa, custom service worker in `src/sw.js` |
| Extension | Chrome MV3 launcher targeting the quick share page |
| Tests | PHPUnit (backend), Vitest and Playwright (frontend) |

## Requirements

- PHP 8.2 or later with `pdo`, and a PDO driver for the database in use
  (`pdo_sqlite` for local work and the test suite, `pdo_pgsql` in production),
  plus `mbstring`, `fileinfo`, `gd`, `zip`, `bcmath`
- Composer 2
- Node 20.19 or later, or 22.12 or later
- A database: SQLite locally, PostgreSQL or MySQL in production

On Debian or Ubuntu the PHP extensions come from:

```sh
sudo apt-get install php8.3-sqlite3 php8.3-gd php8.3-mbstring php8.3-zip php8.3-bcmath
```

## Backend setup

```sh
cd yowl-project/backend
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite      # only for the SQLite default
php artisan migrate
php artisan storage:link            # serves uploaded media from public/storage
php artisan serve
```

The API answers on `http://localhost:8000/api`. `GET /api/health` returns the
service status and is the endpoint to point a monitor at.

### Environment variables

Every variable is listed in `.env.example`. The ones without a usable default:

| Variable | Purpose |
|---|---|
| `APP_KEY` | Generated by `php artisan key:generate` |
| `DB_*` | Database connection |
| `FRONTEND_URL` | Origin allowed by CORS, and base of the links sent by email |
| `MAIL_*` | SMTP credentials for the verification and password reset emails |
| `VAPID_SUBJECT`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | Web push signature |

Generate a VAPID pair with:

```sh
php artisan tinker --execute="echo json_encode(Minishlink\WebPush\VAPID::createVapidKeys());"
```

`VAPID_PUBLIC_KEY` and the frontend `VITE_VAPID_PUBLIC_KEY` must hold the same
value, otherwise the browser subscription is rejected.

## Frontend setup

```sh
cd yowl-project/frontend/yowl-frontend
npm ci

```

| Command | Effect |

| `npm run preview` | Serves the production build |

| `npm run lint` | ESLint with automatic fixes |

## Extension

`extension/` holds an unpacked Chrome MV3 extension that opens the quick share
page of the deployed frontend. Load it from `chrome://extensions` with developer
mode enabled, then set the site URL in its options page.

## API

The OpenAPI description is generated by Scramble and served at `/docs/api` once
the backend runs. The routes below are the stable surface.

### Public

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/health` | Service status |
| GET | `/api/reviews` | Feed, with `search`, `tags`, `sort`, `noAnswers`, `noViews`, `noLikes` |
| GET | `/api/reviews/{review}` | One review, unpublished ones only for their author |
| GET | `/api/comments` | Comment listing |
| GET | `/api/comments/{comment}` | One comment |
| GET | `/api/tags` | Tag listing |
| GET | `/api/kpi` | Community counters |
| POST | `/api/suggestions` | Send a suggestion, 5 requests per minute |

Registration, login, email verification and password reset live in
`routes/auth.php`.

### Authenticated

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/user` | The current user and their roles |
| POST | `/api/reviews` | Create a review, up to 5 images of 5 MB |
| POST | `/api/reviews/{review}` | Update a review, author only |
| DELETE | `/api/reviews/{review}` | Delete a review, author only |
| POST | `/api/comments` | Comment or reply |
| PATCH | `/api/comments/{comment}` | Update a comment, author only |
| DELETE | `/api/comments/{comment}` | Delete a comment, author only |
| POST | `/api/reviews/{review}/react` | Toggle `like` or `dislike` |
| POST | `/api/comments/{comment}/react` | Toggle `like` or `dislike` |
| GET | `/api/notifications` | Notification history and unread count |
| GET | `/api/notifications/unread-count` | Unread count only |
| PATCH | `/api/notifications/read-all` | Mark everything read |
| PATCH | `/api/notifications/{id}/read` | Mark one notification read |
| DELETE | `/api/notifications/{id}` | Delete one notification |
| POST | `/api/reports` | Report a review or a comment, 20 per minute |
| POST | `/api/push/subscribe` | Register a push subscription |
| POST | `/api/push/unsubscribe` | Drop a push subscription |

### Administration

Every route below requires the `admin` role.

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/admin/stats` | Dashboard counters |
| GET | `/api/admin/users` | Member listing, `search` supported |
| PATCH | `/api/admin/users/{user}/role` | Switch between `admin` and `client` |
| PATCH | `/api/admin/users/{user}/ban` | Ban a member and revoke their tokens |
| PATCH | `/api/admin/users/{user}/unban` | Restore a member |
| GET | `/api/admin/reviews` | Review listing |
| PATCH | `/api/admin/reviews/{review}/publish` | Publish a review |
| PATCH | `/api/admin/reviews/{review}/unpublish` | Unpublish a review |
| DELETE | `/api/admin/reviews/{review}` | Delete a review and its media |
| GET | `/api/admin/comments` | Comment listing |
| DELETE | `/api/admin/comments/{comment}` | Delete a comment |
| GET | `/api/admin/reports` | Moderation queue, filtered by `status` |
| PATCH | `/api/admin/reports/{report}` | Close a report, optionally deleting the content |
| GET | `/api/admin/suggestions` | Suggestions, filtered by `status` |
| PATCH | `/api/admin/suggestions/{suggestion}` | Move a suggestion to `read` or `archived` |

## Notifications

A comment, a reply, or a like on a review or a comment notifies the recipient
through two channels at once: a row in the `notifications` table, read by the
bell panel, and a web push message when the user has a live subscription.

The classes live in `app/Notifications`. Add a notification by extending
`ActivityNotification` and implementing `type`, `title`, `body` and `url`; both
channels then work without further wiring.

## Moderation

Members report a review or a comment with a reason and optional details. A
member reports a given piece of content once, and never their own. Reports land
in the admin moderation queue, where they are dismissed, marked handled, or
handled by deleting the reported content in a single action.

```sh
cd yowl-project/backend && php artisan test

```

The backend suite runs on an in-memory SQLite database, which requires the
`pdo_sqlite` extension.

## Deployment

The pipeline in `.github/workflows/ci.yml` runs the backend suite, then the
frontend lint, unit tests and build, on every push and pull request touching
`main` or `dev`.

- Frontend: Vercel, configuration in `frontend/yowl-frontend/vercel.json`. Set
  `VITE_BASE_URL`, `VITE_STORAGE_URL` and `VITE_VAPID_PUBLIC_KEY` in the project
  settings.
- Backend: any PHP host with a persistent database. `backend/Dockerfile` builds
  a PHP 8.2 image with the PostgreSQL driver. Hosts with an ephemeral filesystem
  need object storage for uploaded media, since `storage/app/public` does not
  survive a restart.
- Run `php artisan migrate --force` on deploy, and cache the configuration and
  routes with `php artisan config:cache` and `php artisan route:cache`.
